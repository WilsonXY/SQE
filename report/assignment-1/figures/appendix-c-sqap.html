Plan sections

Management

  • QA is carried by existing roles through the exit policies
  • Triager, implementer, reviewer, release maintainers, maintainers handling reports
  • High tier: independent reviewer who did not write the change and does not own its area in CODEOWNERS

Documentation

  • This written QA plan (Table 3.2)
  • Each card records its tier and acceptance criteria
  • High tier: endpoints, permissions and sync effect listed at design
  • Coverage report; approval lists what was checked; published advisory

Standards, practices and conventions

  • ISO/IEC 25010:2023 quality model
  • OWASP ASVS 5.0.0 (authentication, sessions, authorisation)
  • WCAG 2.2 AA, up from 2.1 AA
  • IEEE 1012-2024: more serious failure, more verification (risk tiers)
  • Measure: test coverage

Reviews and audits

  • Triage check by someone other than the requester
  • Design review and independent Verify review (High tier)
  • PR review by another maintainer
  • Release check of Verify evidence
  • Occasional external security audit, funded from outside (OSTIF)

Test

  • Existing: linting, type checking, Vitest unit tests, migration check, Playwright end-to-end and visual regression, CodeQL
  • Added: coverage report, authorisation test matrix, automated WCAG 2.2 AA checks, a regression test for each escaped defect

Problem reporting and corrective action

  • Private vulnerability reporting and coordinated disclosure
  • No release while a critical or high finding is open
  • Each escaped defect: regression test, review of the check that missed it, tier of its area checked again

Risk management and change control

  • Risk tier set at triage decides which checks a card must pass
  • Tier set too low is the main risk; corrected after each escaped defect
  • Every change moves through the board, a pull request and CI
  • Tools: GitHub, CI, CodeQL, Vitest, Playwright
